# 遠隔工事監視システム

工事現場の iPhone から本部の Mac へ映像をリアルタイム伝送し、最大 25 現場をタイル表示・録画するシステムの設計資料です。

現在は **基本設計フェーズ（v0.1）** です。アプリケーションの実装コードはまだ含みません。

## 設計上の結論

- 利用者向けアプリは、現場用 iOS アプリと本部用 macOS アプリの 2 つとする。
- 携帯回線の NAT 越え、端末認証、遠隔画質制御、安定した録画のため、内部基盤として制御 API、WebRTC SFU/TURN、録画サービス、データベース、録画ストレージを設ける。
- iOS は通常のバックグラウンド状態ではカメラを継続利用できない。現場端末を会社管理の専用端末として監督対象にし、MDM の App Lock（Single App Mode）でアプリを常時フォアグラウンドに固定することを 24 時間運用の前提とする。
- ライブ映像は WebRTC、映像コーデックは H.264、録画は Mac の表示状態に依存しない中央録画を基本とする。
- 本部画面は 1 画面 25 タイルを上限とし、各タイルを 16:9、工事名称を左下、撮影時刻を右下に表示する。
- 遠隔画質設定は「保証値」ではなく「希望する上限」とする。回線混雑や端末温度上昇時は、安全性と接続継続を優先して自動的に下げ、希望値と実測値を本部画面に併記する。
- Mac の「表示画質」と iPhone の「送信・録画画質」は別の設定として扱う。25 タイルでは軽量レイヤーを表示し、詳細表示時だけ高画質を購読できる構成を検証する。
- 回線断中の一定量の映像欠落は許容する。初期版では iPhone に映像を蓄積せず、復旧後にライブ送信を自動再開し、欠落区間を本部の録画・再生画面で明示する。

## 次の工程へ進む前に決める事項

設計では暫定値を置いていますが、実装着手前に少なくとも次を確定します。

1. 同時接続現場数と将来の最大登録現場数
2. 標準画質、許容遅延、音声の要否
3. 録画の既定モードと保存日数
4. 録画先をクラウド、社内サーバー/NAS、または両方のどれにするか
5. 利用する iPhone 機種、回線、設置環境、MDM 製品
6. 本部 Mac の台数、機種、ディスプレイ解像度
7. 端末パスコードによる機密性と、再起動後の無人復旧のどちらを優先するか
