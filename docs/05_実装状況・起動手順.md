# 遠隔工事監視システム 実装状況・起動手順

| 項目 | 内容 |
|---|---|
| バージョン | 動作プロトタイプ v0.2 |
| iOS | iOS 18 以降、SwiftUI、AVFoundation |
| macOS | macOS 15 以降、SwiftUI |
| 言語 | Swift 6、strict concurrency |
| プロジェクト生成 | XcodeGen 2.45.4 以降 |
| 検証環境 | Xcode 26.6、Swift 6.3.3、Apple silicon Mac |

## 1. このプロトタイプで確認できること

本プロトタイプは、画面だけの静的なモックではない。iOSでは実際のカメラ権限とAVFoundationのキャプチャセッションを使用し、macOSでは品質変更、録画開始・停止、欠落区間、保存期間変更の状態遷移を操作できる。

ただし、映像伝送、中央録画、認証は実サーバーへ接続していない。これらは後から実装を差し替えられるよう、アプリUIからサービス境界を分離している。

## 2. iOSアプリ

### 2.1 実装済み

- 初回起動時に工事名称を登録する。
- 工事名称は前後空白を除去し、改行を拒否し、1〜80文字に制限する。
- 工事名称をUserDefaultsに保存し、次回起動時は再入力させない。
- カメラ権限を要求する前に利用目的と音声を扱わないことを説明する。
- 背面広角カメラを優先してAVCaptureSessionを構成する。
- カメラセッションの構築とstartRunningをメインスレッド外で実行する。
- カメラプレビュー上に工事名称、接続状態、品質、最終送信時刻を重ねる。
- 通常画面に配信停止ボタンを置かない。
- 設定を開いている間もカメラセッションを維持する。
- 設定から工事名称を変更する。
- カメラ権限拒否時はiOS設定への導線を表示する。
- ProcessInfoの温度通知を監視し、seriousでは品質制限、criticalでは一時停止する。
- アプリがアクティブな間は画面の自動ロックを抑止する。
- バックグラウンドではカメラと模擬伝送を停止し、復帰時に自動再開する。

### 2.2 模擬実装

`VideoTransport`を映像・制御通信の境界とし、現在は`PreviewVideoTransport`を使用する。

模擬伝送層は次を再現する。

- 初回接続と再接続
- 1秒ごとの最終送信時刻更新
- 本部からの希望品質変更
- 温度上昇時の実効品質低下
- オフラインと復旧

カメラフレームはネットワークへ送っていない。WebRTC SDKを導入するときは`VideoTransport`の実装を追加し、既存画面と状態モデルを維持する。

## 3. macOSアプリ

### 3.1 監視画面

- 既定は5×5の25タイルとする。
- 1、4、9、16、25画面を切り替えられる。
- 利用可能領域からタイル寸法を計算し、常に16:9を維持する。
- 左下に工事名称、右下にJSTの撮影時刻を表示する。
- LIVE、遅延、再接続、OFFLINE、カメラ停止、熱保護を文字・アイコン・色で示す。
- OFFLINE等では最後の映像を暗く固定した表現にし、撮影時刻を進めない。
- 選択現場のインスペクターに、希望品質、端末適用品質、実測品質を分けて表示する。
- 矢印キー、Return、Esc、ダブルクリックによる監視操作に対応する。

### 3.2 品質と録画操作

品質変更は、要求を送った直後に適用済みと表示しない。

```text
未操作 → 端末へ送信中 → 適用済み
                     └→ オフライン時は再接続待ち
```

録画もライブ接続とは分離し、中央録画サービスのACKを模擬した遷移を行う。

```text
未録画 → 録画開始中 → 録画中 → 録画停止中 → 未録画
```

品質コマンドと録画コマンドは別のTaskで管理し、同時操作が互いをキャンセルしない。

### 3.3 録画検索と保存期間

- 工事名称、期間、欠落有無で模擬録画を検索する。
- 欠落区間を実時間タイムライン上へ表示する。
- 欠落位置では映像がないことと理由を表示する。
- 保存期間短縮時は、変更前後の日数、削除件数、容量、対象期間、開始予定、復元不可を確認する。
- 確認前は設定値を変更しない。

## 4. 共有モジュール

`CHShared`はiOS/macOSに共通する次の型と純粋ロジックを提供する。

- `QualityPreset`、`VideoMetrics`
- `ConnectionStatus`、`RecordingStatus`
- `SiteSnapshot`
- `RecordingItem`、`RecordingGap`
- `SiteNameValidator`
- `RecordingCalculations`

録画欠落計算では、重複区間のマージ、録画範囲へのクリップ、不正な逆転区間の除外を行う。

## 5. セットアップ

### 5.1 必要なツール

```bash
xcodebuild -version
swift --version
xcodegen --version
```

XcodeGenがない場合はHomebrewで導入する。

```bash
brew install xcodegen
```

### 5.2 Xcodeプロジェクト生成

```bash
make project
open CHRemoteMonitor.xcodeproj
```

`project.yml`を正本とする。生成された`.xcodeproj`、Info.plist、entitlementsは直接変更せず、設定変更後に`make project`で再生成する。

### 5.3 テストとビルド

```bash
make test
make build-ios
make build-ios-device
make build-macos
make verify
```

`make verify`は共有テスト、iOS Simulator向けビルド、macOS向けビルドをまとめて実行する。`make build-ios-device`は署名せずにiPhoneOS/arm64向けのコンパイルまで確認する。

### 5.4 実機起動

iPhone実機では、XcodeのSigning & Capabilitiesで開発チームを選択し、組織で使用可能なBundle Identifierへ変更する。現在のBundle Identifierはプロトタイプ用である。

実機で次を確認する。

1. カメラ権限を許可する。
2. 自動ロックが抑止されることを確認する。
3. 充電状態、端末温度、設置ケース、直射日光、通信回線を確認する。
4. MDMのSingle App Modeを設定し、アプリを常時フォアグラウンドに保つ。

iOSの制約上、通常のバックグラウンド状態でカメラを24時間使用することはできない。24時間運用は会社所有の監督対象端末、常時給電、Single App Mode、温度管理を前提とする。

## 6. 実サービス接続時の差し替え箇所

| 現在 | 実サービス接続後 |
|---|---|
| `PreviewVideoTransport` | WebRTC publish、制御WebSocket、再接続を行うtransport |
| `HQMonitorStore.preview()` | REST snapshotと制御WebSocketを購読するrepository |
| 工事現場風プレースホルダー | WebRTCの受信video renderer |
| 模擬録画ACK | 中央録画サービスのACK |
| 模擬録画一覧 | 録画検索APIと署名付き再生URL |
| 模擬保存期間変更 | 影響見積API、削除予約API、監査ログ |

アプリへ固定トークン、TURN共有パスワード、本番URLを埋め込まない。端末登録と組織認証を実装し、短寿命の接続情報をAPIから取得する。

## 7. 次工程の完了条件

1. 検証用SFU/TURNへiPhone一台を接続し、Mac一台で映像を表示できる。
2. Macからの品質指示に対し、iPhoneの適用ACKと実測値が一致する。
3. 中央録画を開始・停止し、欠落メタデータ付きで検索・再生できる。
4. 25ストリーム時のMac CPU/GPU/メモリと、iPhoneの温度・通信量を測定できる。
5. 24時間以上の連続PoCで、再接続、熱保護、録画カバレッジを評価できる。
6. 認証、認可、監査ログ、保存期間削除予約を実サービスで確認できる。
