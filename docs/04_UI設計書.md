# 遠隔工事監視システム UI設計書

| 項目 | 内容 |
|---|---|
| 文書版 | 0.1 |
| 作成日 | 2026-08-28 |
| 対象 | 現場用iOSアプリ、本部用macOSアプリ |
| 前提 | 回線断中の一定量の映像欠落を許容する |

## 1. UI設計方針

### 1.1 最優先事項

UIで防ぐべき誤認を、次の順で優先する。

1. 停止した最終フレームをライブ映像と誤認しない。
2. ライブ映像が見えていることと、中央録画が成功していることを混同しない。
3. 本部が希望した画質と、端末適用値・実測受信値・Mac表示画質を混同しない。
4. 許容した映像欠落を、連続して録画できたように見せない。
5. 保存期間の短縮で削除される録画の範囲を理解せず確定しない。
6. 現場iPhoneの偶発操作で送信を停止しない。

### 1.2 共通原則

- 状態は色だけで表さず、アイコン、短い日本語、位置を組み合わせる。
- 監視画面には現在の事実を表示し、操作要求と適用結果を分ける。
- 工事名称は表示用とし、内部IDを画面の主情報にしない。
- タイムスタンプは原則として撮影時刻とし、`JST`を明示する。
- 技術用語の`ICE`、`SFU`、`ACK`、`thermal serious`は運用者向け日本語へ変換する。
- 連続する正常状態を派手に点滅させず、異常だけが自然に目に入るようにする。
- 音声を取得しないことを初回設定と設定画面に明記する。

## 2. 情報設計

### 2.1 iOS

現場アプリは「配信を操作するアプリ」ではなく「配信状態を確認する専用端末画面」とする。

```text
初回設定
  ├─ 工事名称入力
  └─ カメラ利用説明・権限

通常運用
  ├─ 配信中
  ├─ 接続中・再接続中
  ├─ 本部へ未送信
  ├─ 熱保護中
  └─ カメラ・権限異常

管理者設定
  ├─ 工事名称
  ├─ 配信状態・診断
  └─ 端末情報
```

通常画面には配信停止、ログアウト、登録解除を置かない。

### 2.2 macOS

```text
ライブ監視
  ├─ 最大25タイル
  └─ 選択現場インスペクター

録画
  ├─ 録画検索
  ├─ 再生・欠落タイムライン
  └─ 書き出し

設定
  ├─ 録画既定モード
  ├─ 保存期間
  ├─ 容量予測
  └─ 欠落・容量不足時の方針
```

ライブ監視と録画再生は状態を共有するが、表示画面を分ける。録画再生中もライブ監視を別ウインドウまたは元画面で維持できる構成を将来検討する。

## 3. iOS UI

### 3.1 初回設定: 工事名称

```text
┌──────────────────────────────┐
│                              │
│ 現場カメラを設定します        │
│                              │
│ 工事名称を入力すると、         │
│ 本部への映像送信を開始します。 │
│                              │
│ 工事名称                      │
│ [ ○○道路改良工事            ] │
│                              │
│ [ 保存して監視を開始         ] │
│                              │
│ カメラのみ使用。音声は取得なし │
└──────────────────────────────┘
```

#### 要素

| 要素 | 仕様 |
|---|---|
| 見出し | `現場カメラを設定します` |
| 説明 | `工事名称を入力すると、カメラを起動して本部への映像送信を開始します。` |
| 入力 | `工事名称`、1〜80文字、前後空白除去、改行不可 |
| 主操作 | `保存して監視を開始` |
| 補足 | `開始時にカメラへのアクセスを確認します。音声は取得しません。` |
| エラー | `工事名称を入力してください。`または`工事名称は80文字以内で入力してください。` |

MDMから端末登録情報を取得できない場合は一般入力欄を増やさず、`この端末はまだ登録されていません。管理者へ連絡してください。`と表示する。

主ボタンを押した後、OSのカメラ権限要求前に使用目的を説明する。権限許可後は追加操作なしで配信を開始する。

### 3.2 配信中

画面全面をカメラプレビューとし、上部に配信状態、下部に工事名称と必要最小限の状態を重ねる。

```text
┌──────────────────────────────┐
│ ● 本部へ配信中            ⚙  │
│                              │
│                              │
│       カメラプレビュー        │
│                              │
│                              │
│ ○○道路改良工事               │
│ 希望 STANDARD                 │
│ 実測 720p / 14.8fps           │
│ 通信 5G・良好  電源 接続中    │
└──────────────────────────────┘
```

表示優先順位:

1. 本部へ実際に送信できているか
2. 工事名称
3. 最終送信時刻
4. 実測画質
5. 電源・温度

`配信中`は制御接続だけでなく、映像フレームが中央へ届いていることを中央状態から確認して表示する。設定ボタンは44×44pt以上とし、設定画面を開いても撮影と送信を継続する。

通常画面には送信停止ボタンを設けない。画質は読み取り専用で、本部からのみ変更する。

### 3.3 回線断・再接続

```text
┌──────────────────────────────┐
│                              │
│   本部と接続できません        │
│                              │
│ 映像は端末に保存せず、         │
│ 自動的に再接続します。         │
│                              │
│ 次の再試行まで 8秒            │
│                              │
│ 最終送信 13:41:52             │
│ 状態     再接続中              │
└──────────────────────────────┘
```

- ローカルプレビューを暗くし、本部へ届いていないことを中央メッセージで示す。
- `回線を確認しています。復旧すると自動で配信を再開します。`と説明する。
- `切断中の映像は本部へ送信・録画されません。`を明示する。
- 再試行を利用者に要求しない。再接続は常に自動とする。
- 復旧時は非モーダルに`配信を再開しました。欠落時間 1分42秒`と表示する。
- 短い断線ごとに確認ダイアログを出さない。

### 3.4 熱保護

画質を下げても継続できる状態と、安全上停止が必要な状態を分ける。

| 状態 | 見出し | 本文 |
|---|---|---|
| 縮退継続 | `端末温度が上昇しています` | `端末を保護するため画質を下げて配信しています。` |
| 一時停止 | `高温のため配信を一時停止しています` | `温度が下がると自動で配信を再開します。` |

縮退中は`希望 STANDARD → 実測 LOW`を表示する。熱保護を現場で無効化する操作は設けない。必要な現場対応として、直射日光、通気、筐体を確認する文言を表示する。

### 3.5 設定

設定入口は管理者PIN等で保護する。設定画面の上部に`設定中も配信は継続しています`と表示する。

| セクション | 内容 | 編集 |
|---|---|---|
| 現場情報 | 工事名称 | 可 |
| 配信状態 | 本部設定画質、実測画質、接続、最終送信、回線、電源、温度 | 読取専用 |
| 端末情報 | siteId末尾、deviceId末尾、アプリ/OS版 | 読取専用 |
| 管理者診断 | 接続診断、カメラ権限、ログ送信 | 管理者のみ |

工事名称保存後は`工事名称を変更しました`、中央同期失敗時は`変更を本部へ送信できませんでした。接続復旧後に再送します。`と表示する。

## 4. macOS UI

### 4.1 アプリシェル

```text
┌ 工事監視  オンライン22/25・録画中18     表示25  全画面 ┐
├──────────┬─────────────────────────────────────┤
│ ライブ監視 │                                     │
│ 録画       │        最大25タイル                 │
│ 設定       │                                     │
│            │                                     │
│ 全現場     │                                     │
└──────────┴─────────────────────────────────────┘
```

- 上部: 全体状態、表示数、全画面
- 左: ライブ監視、録画、設定、監視グループ
- 中央: 選択した画面
- 右: ライブ画面で選択現場のインスペクター

監視に集中する全画面モードではサイドバーを隠す。タイル位置はオフラインや復旧によって自動で入れ替えず、利用者が変更するまで固定する。

### 4.2 タイルレイアウト

| 現場数 | レイアウト |
|---:|---:|
| 1 | 1×1 |
| 2〜4 | 2×2 |
| 5〜9 | 3×3 |
| 10〜16 | 4×4 |
| 17〜25 | 5×5 |

25タイルでは、常時表示を次の4項目へ絞る。

- 接続状態
- 録画状態
- 工事名称
- 撮影タイムスタンプ

画質、ビットレート、遅延、端末温度、電源、コマンド履歴は右インスペクターへ分離する。ただし異常時は`画質制限中`や`録画失敗`を短く追加する。

### 4.3 タイル

```text
┌────────────────────────────────────┐
│ ● LIVE                   ● REC      │
│                                    │
│               映像                 │
│                                    │
│ 工事名称       2026/08/28 13:42:18 │
└────────────────────────────────────┘
```

| 位置 | 内容 |
|---|---|
| 左上 | 受信状態。`LIVE`、`遅延`、`再接続中`、`OFFLINE`等 |
| 右上 | 録画サービスからACKされた録画状態 |
| 左下 | 工事名称。1行省略、ポインターとVoiceOverで全文 |
| 右下 | 撮影時刻。等幅数字、JST |

下辺に黒の半透明グラデーションを置く。5×5で名称と時刻が競合する場合は時刻を優先し、名称を省略する。選択は明瞭な枠で示し、ダブルクリックまたはReturnで拡大、Escで一覧へ戻る。

### 4.4 映像状態

| 状態 | タイル表示 | 映像の扱い |
|---|---|---|
| 正常 | `● LIVE` | 通常表示 |
| 遅延 | `△ 遅延 7秒` | 映像を表示し、警告を重ねる |
| 映像停止 | `■ 映像停止 18秒` | 最終フレームを暗く固定 |
| 再接続 | `↻ 再接続中 00:12` | 最終フレームを暗く固定 |
| オフライン | `■ OFFLINE 03:28` | 最終フレームを暗く固定。長時間後はプレースホルダー |
| カメラ停止 | `! カメラを利用できません` | 状態プレースホルダー |
| 画質縮退 | `△ 画質制限中` | 映像は継続 |

停止時は即座に`LIVE`を消し、中央に状態、最終受信時刻、停止継続時間を表示する。右下の撮影時刻は最後のフレームの時刻で止め、Macの現在時刻へ更新しない。

### 4.5 録画状態

ライブ状態と完全に分離し、中央録画サービスの応答を正とする。

```text
未録画
録画開始中…
● 録画中 01:24:18
録画停止中…
! 録画失敗
! 保存先容量不足
△ 録画途切れあり
```

録画開始要求直後に赤いRECを表示しない。開始ACK後に初めて`録画中`へ変える。録画失敗は一時通知だけで終わらせず、タイル、全体集計、録画画面へ残す。

停止操作はスイッチではなく`録画を停止…`ボタンとし、対象名を含む確認を行う。全現場停止は通常の現場操作から離れた管理メニューに置く。

### 4.6 現場インスペクター

タイルを選択すると右側に開く。

```text
○○道路改良工事
LIVE・最終受信 1秒前

希望画質     STANDARD
端末適用     STANDARD
実測受信     1280×720 / 14.8fps
タイル表示   640×360
ビットレート 742kbps
遅延         0.8秒
端末温度     正常
録画         録画中

[送信・録画画質 ▼]
[録画を停止…]
```

画質変更は次の状態を表示する。

```text
端末へ送信中
端末応答待ち
適用済み 13:45:12
一部適用・端末温度により制限
拒否
タイムアウト
```

オフライン端末には`端末はオフラインです。再接続時にHIGHを適用します。`と表示し、成功扱いにしない。HIGHは一時適用時間を選べる設計を将来検討する。

### 4.7 録画検索・再生

検索条件は、工事名称、撮影日、録画状態、欠落の有無、保存期限を基本にする。内部の5分ファイル分割は画面へ出さず、連続した論理録画として扱う。

```text
┌ 録画一覧 ───────┬──────── 16:9再生 ────────┐
│ 12:00–13:00     │                          │
│ 11:00–12:00     │ 工事名称        撮影時刻 │
│ 欠落 2分14秒     │                          │
└────────────────┴──────────────────────────┘
                    ━━━━━━━░░━━━━△━━━━━━
                           欠落区間
```

- 欠落区間を斜線または空白として表示し、開始・終了・長さを記載する。
- 欠落部分を無言で飛ばさず、実時間の時間軸を維持する。
- `この区間には映像がありません（通信断: 2分14秒）`と表示する。
- 録画ごとにカバレッジを表示可能にする。例: `23時間42分 / 24時間（98.8%）`。
- 書き出し時にも欠落メタデータを含め、必要なら黒画面と欠落文言を挿入する。

### 4.8 録画・保存設定

```text
録画・保存設定

既定録画モード  [ 手動録画 ▼ ]
保存期間        [ 30日 ▼ ]
回線断中        欠落を許容・端末保存なし
容量不足時      新規録画を停止して通知

25現場・STANDARD・30日
必要容量の概算  約9TB

                         [設定を保存]
```

保存期間の短縮は通常変更と分け、影響を確認する。

```text
保存期間を30日から7日に変更します

削除対象       2,431件
推定容量       1.8TB
対象期間       2026/07/30〜2026/08/20
削除開始       2026/08/29 03:00 JST

削除後は復元できません。

[キャンセル] [保存期間を7日に変更]
```

保存ボタンを押すまで適用しない。短縮確認には旧値、新値、対象件数、容量、期間、削除開始、復元不可を示す。可能なら削除開始まで取消可能な猶予を設ける。

## 5. 欠落許容のUI仕様

欠落を許容することと、欠落を隠すことを区別する。

### 5.1 ライブ

- 最後のフレーム受信が閾値を超えた時点で`LIVE`を外す。
- 最終フレームを暗く固定し、撮影時刻も停止する。
- `再接続中`または`OFFLINE`、最終受信時刻、停止時間を表示する。
- 端末復旧後は同じタイル位置でライブを再開する。
- 数秒の瞬断はモーダル通知せず、履歴へ記録する。

### 5.2 録画

- 欠落開始は最後の正常フレーム時刻、終了は再開後最初のフレーム時刻で記録する。
- タイムライン上で録画あり、回線断、録画停止、録画障害を区別する。
- 欠落区間の前後を詰めて連続映像に見せない。
- 検索結果、再生、書き出し、監査へ欠落情報を残す。

### 5.3 復旧通知

```text
配信を再開しました
欠落時間: 1分42秒
切断: 13:41:52
再開: 13:43:34
```

iPhoneでは数秒表示、本部では履歴として保持する。

## 6. キーボード・アクセシビリティ

### 6.1 iOS

- タップ領域は44×44pt以上。
- Dynamic Typeに対応する。
- VoiceOver順序は配信状態、工事名称、最終送信、画質、設定。
- 秒数やビットレートを毎秒読み上げず、状態変化時だけ通知する。
- 点滅表示を使用しない。
- 明るい映像上の文字には濃色背景またはグラデーションを敷く。

### 6.2 macOS

- 矢印キー: タイル移動
- Return: 選択タイルを拡大
- Esc: 拡大・インスペクターを閉じる
- `⌘1`: ライブ監視
- `⌘2`: 録画
- `⌘,`: 設定
- VoiceOver例: `○○道路改良工事、ライブ、録画中、撮影時刻13時42分18秒`
- フォーカス、選択、警告を同じ枠表現にしない。
- 状態をグレースケールでも文字と形から識別できるようにする。
- macOSのコントラスト・透明度・視差低減設定へ対応する。

## 7. 4K・25タイル時の目安

4K・16:9全画面では、映像領域だけなら1タイル約768×432pxになる。ツールバーと間隔を考慮し、監視専用全画面モードでタイル面積を最大化する。

| 要素 | 初期目安 |
|---|---:|
| 工事名称 | 14〜16pt、Medium |
| タイムスタンプ | 13〜14pt、等幅数字 |
| 状態表示 | 12〜13pt、Medium |
| タイル間隔 | 2〜4px |
| 選択枠 | 2〜3px |
| 小さい通常文字のコントラスト | 4.5:1以上 |

表示サイズ`大`を将来提供し、4×4を上限としてページを増やす。25タイルを維持するために文字を極端に縮小しない。

## 8. UI受入条件

1. WebRTC接続を維持したまま映像フレームを停止すると、規定時間内に`LIVE`が消える。
2. 映像停止時、右下の撮影時刻が進まない。
3. 全く動きのない現場でも新しいフレームが届いていれば`LIVE`を維持する。
4. ライブ映像を維持したまま録画ワーカーを停止すると、RECが`録画失敗`へ変わる。
5. 希望HIGH、端末適用STANDARDの場合に希望、適用、実測、タイル表示を分離して表示する。
6. オフライン端末への画質指示を`適用済み`と表示しない。
7. 17秒の回線断が、再生タイムラインと書き出し情報に17秒の欠落として残る。
8. オフラインから復帰してもタイル位置が変わらない。
9. 5×5で全タイルの名称、時刻、接続、録画状態が重ならない。
10. 色覚特性シミュレーションとグレースケールでも全状態を判別できる。
11. 保存期間を30日から7日に短縮すると、削除件数、容量、期間、開始時刻、復元不可が確定前に表示される。
12. 現場iPhoneの通常画面から偶発的に配信を停止できない。
13. 設定画面を開いている間もiPhoneの撮影・送信が継続する。
14. 工事名称が長い、同名、Unicodeを含む場合も別現場と取り違えない。
15. VoiceOverとキーボードだけで主要状態の確認とMac画面移動ができる。
